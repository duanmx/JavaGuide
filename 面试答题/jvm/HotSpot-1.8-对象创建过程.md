# HotSpot 1.8 对象创建过程

## 概述

在 Java 中，使用 `new` 关键字创建对象是最常见的方式。HotSpot 虚拟机在底层创建对象需要经过以下 **6 个步骤**。

## 完整流程

```
new User("张三")
    ↓
① 类加载检查
    ↓
② 分配内存
    ↓
③ 内存空间初始化为零值
    ↓
④ 设置对象头（Mark Word + 类型指针）
    ↓
⑤ 执行 <init> 方法（构造方法）
    ↓
⑥ 返回对象引用
```

---

## 步骤详解

### ① 类加载检查

JVM 遇到 `new` 指令时，首先检查这个类是否已经被加载到元空间（Metaspace）。

- 如果**未加载** → 触发类加载流程（加载 → 验证 → 准备 → 解析 → 初始化）
- 如果**已加载** → 直接进入下一步

> 只有第一次 `new` 某个类时才会触发类加载，后续创建直接跳过。

---

### ② 分配内存

类加载通过后，JVM 在**堆的 Eden 区**为新对象分配内存。

#### 两种分配方式

| 方式 | 适用场景 | 原理 |
|------|---------|------|
| **指针碰撞**（Bump the Pointer） | 内存规整（Serial、ParNew GC） | 将指针向空闲方向移动对象大小的距离 |
| **空闲列表**（Free List） | 内存不规整（CMS GC） | 在列表中找一块足够大的空间分配 |

#### 并发安全方案

多线程同时分配内存时，HotSpot 采用以下两种方案保证安全：

**方案一：CAS + 失败重试（乐观锁）**

直接在堆内存中通过 CAS 操作分配，失败则重试，直到成功。

**方案二：TLAB（Thread Local Allocation Buffer）**

- 每个线程预先在 Eden 区分配一块私有缓冲区（TLAB）
- 线程在自己的 TLAB 中分配内存，**无需加锁**
- TLAB 用完后，再通过 CAS 申请新的 TLAB

```
分配优先级：
TLAB 分配（首选，无锁）
    ↓ TLAB 空间不足
CAS 申请新 TLAB
    ↓ 对象超过 TLAB 容量（大对象）
直接 CAS 在 Eden 区分配
```

> TLAB 默认开启，可通过 `-XX:+UseTLAB` / `-XX:-UseTLAB` 控制。

---

### ③ 内存空间初始化为零值

分配完内存后，JVM 将对象内存（**不包括对象头**）全部初始化为零值：

| 字段类型 | 零值 |
|---------|------|
| `int` | `0` |
| `long` | `0L` |
| `float` | `0.0f` |
| `double` | `0.0d` |
| `boolean` | `false` |
| `char` | `'\u0000'` |
| 引用类型 | `null` |

> **注意**：引用类型的字段初始化为 `null`，只表示"这个引用不指向任何对象"。嵌套对象（如 `new Address()`）在此时**并未创建**，它们会在步骤 ⑤ 执行构造方法时才被创建。

#### 疑问：对象里面还有对象，零值初始化怎么处理？

```java
public class User {
    private int age;              // 基本类型
    private String name;          // 引用类型
    private Address address;      // 引用类型（对象里面还有对象）
    private List<String> hobbies; // 引用类型
}
```

零值初始化后：

```
User 对象内存
┌─────────────────────────┐
│ 对象头                   │  ← 不初始化
├─────────────────────────┤
│ age     = 0             │  ← 基本类型零值
│ name    = null          │  ← 引用类型零值（不是 String 对象！）
│ address = null          │  ← 引用类型零值（不是 Address 对象！）
│ hobbies = null          │  ← 引用类型零值（不是 List 对象！）
└─────────────────────────┘
```

**嵌套的 Address、List 对象此时根本没有创建**，只有 `null` 引用。这些嵌套对象是在步骤 ⑤ 执行构造方法或字段初始化时，才通过 `new` 单独创建的，父对象只存它们的引用地址。

---

### ④ 设置对象头

JVM 为对象设置**对象头（Object Header）**，以 64 位系统（开启指针压缩）为例：

```
对象头（共 12 字节）
┌──────────────────────────────────────────────┐
│ Mark Word（8 字节）                           │
│  - hashCode（对象哈希码）                      │
│  - GC 分代年龄（0~15）                        │
│  - 锁状态标志（无锁/偏向锁/轻量级锁/重量级锁） │
│  - 偏向线程 ID（偏向锁状态下记录线程）          │
├──────────────────────────────────────────────┤
│ Klass Pointer（4 字节，开启指针压缩）          │
│  → 指向元空间中该类的元信息                     │
└──────────────────────────────────────────────┘
```

> 如果是数组对象，对象头还额外包含 **4 字节的数组长度字段**。

#### 疑问：锁状态标志和偏向线程 ID 有什么作用？

Mark Word 中的锁状态是 JVM 对 `synchronized` 的**渐进式优化**，锁有四个级别：

```
无锁 → 偏向锁 → 轻量级锁 → 重量级锁
        ↑         ↑          ↑
     1个线程    2个线程     多线程竞争
     反复访问    交替访问    同时访问
```

**偏向锁**：只有一个线程反复进入同步块，根本没有竞争。
- 第一次进入时，把**线程 ID 记录在对象头的「偏向线程 ID」字段**
- 后续同一线程再来，检查线程 ID 匹配 → 直接进入，**无需任何加锁操作**（极快）
- 其他线程来竞争 → 偏向锁失效，升级为轻量级锁

**轻量级锁**：两个线程交替访问，不会同时进入。
- 用 CAS 操作竞争，失败则升级为重量级锁

**重量级锁**：多线程同时竞争，真正发生冲突。
- 获取不到锁的线程 → 阻塞（挂起，让出 CPU），性能最差

> **偏向线程 ID 的核心作用**：记住"谁独占过这把锁"，下次同一个线程来时直接放行，省掉加锁的所有开销，这是对**单线程反复访问同步块**场景的极致优化。

---

### ⑤ 执行 `<init>` 方法（构造方法）

按照以下顺序执行初始化逻辑：

1. **父类构造方法**（`super()`）
2. **字段声明时的赋值**（如 `int age = 25`）
3. **实例代码块**（`{ ... }`）
4. **构造方法体**

此阶段会覆盖步骤 ③ 的零值，将字段赋为真实的初始值。如果字段中包含 `new` 表达式（如 `private Address address = new Address()`），嵌套对象也在此时被创建。

---

### ⑥ 返回对象引用

构造方法执行完毕后，JVM 将新创建对象的**引用（内存地址）** 返回，赋值给栈中的局部变量。

```
虚拟机栈（栈帧）
┌──────────────────┐
│ 局部变量表        │
│  user = 0x00FF   │  ← 指向堆中对象的地址
└──────────────────┘
         ↓
堆（Heap）
┌──────────────────┐
│ User 对象         │
│ 对象头：          │
│   hashCode: 0    │
│   分代年龄: 0    │
│   锁状态: 无锁   │
│   类型指针 → User.class（元空间）
├──────────────────┤
│ name = "张三"    │  ← 引用，指向字符串常量池中的对象
│ age = 25         │  ← 基本类型，直接存储值
└──────────────────┘
```

---

## 对象内存大小

对象的内存大小 = **对象头 + 基本类型字段 + 引用字段（4 字节）+ 对齐填充**

- 引用字段只存储**地址（4 或 8 字节）**，不包含被引用对象的大小
- 被引用的对象在堆中**独立分配内存**
- 对象大小必须是 **8 字节的整数倍**（对齐填充）

示例（64 位 JVM，开启指针压缩）：

```java
public class User {
    private int age;           // 4 字节
    private String name;       // 4 字节（仅引用）
    private Address address;   // 4 字节（仅引用）
}
// User 对象大小 = 12（对象头）+ 4 + 4 + 4 = 24 字节
```

#### 疑问：对象内存大小不包含引用的对象，只包含引用本身？

**是的。** Java 对象内存中只存储引用（地址），被引用的对象在堆中独立分配。

```
64 位 JVM，开启指针压缩（默认）：引用 = 4 字节
64 位 JVM，关闭指针压缩：       引用 = 8 字节
```

完整内存占用示例：

```
User 对象本身：          24 字节（只含引用）
    ↓ name 引用
String "张三" 对象：     ~24 字节
    ↓ value[] 引用
char[] 数组对象：        ~24 字节
─────────────────────────────
总计约                   72 字节（但 User 本身只占 24 字节）
```

> 不管 name 指向的 String 有多大，User 对象本身只占 4 字节存这个引用。每个对象都是**独立分配**的，父对象里只存子对象的引用地址。

---

## 一句话总结

> HotSpot 1.8 创建对象：**检查类是否加载 → 在堆中分配内存（TLAB/CAS）→ 零值初始化 → 设置对象头 → 执行构造方法 → 返回引用**。嵌套对象在构造方法中单独创建，父对象只存储其引用地址。
