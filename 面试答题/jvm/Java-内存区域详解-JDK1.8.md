# Java 内存区域详解（JDK 1.8）

## 整体架构

```
JVM 运行时数据区
│
├── 线程私有（每个线程独立一份）
│   ├── 程序计数器（PC Register）
│   ├── 虚拟机栈（VM Stack）
│   └── 本地方法栈（Native Method Stack）
│
└── 线程共享（所有线程共同使用）
    ├── 堆（Heap）
    └── 元空间（Metaspace）← JDK 1.8 取代永久代
```

---

## 各区域详解

### 一、程序计数器（PC Register）

| 属性 | 说明 |
|------|------|
| 线程属性 | 线程私有 |
| 存储内容 | 当前线程执行到的字节码行号 |
| 异常 | **无**（唯一不会发生 OOM 的区域） |
| 内存来源 | JVM 内存 |

作用：线程切换时能恢复到正确的执行位置；执行 Native 方法时，PC 值为 undefined。

---

### 二、虚拟机栈（VM Stack）

| 属性 | 说明 |
|------|------|
| 线程属性 | 线程私有 |
| 存储内容 | 每个方法调用对应一个栈帧 |
| 异常 | StackOverflowError（递归太深）/ OutOfMemoryError |
| 内存来源 | JVM 内存 |

每个栈帧包含：

```
┌─────────────────────┐
│ 栈帧（Stack Frame）  │
├─────────────────────┤
│ ① 局部变量表         │  ← 方法参数 + 局部变量（基本类型值 + 引用类型地址）
│ ② 操作数栈           │  ← 计算中间结果
│ ③ 动态链接           │  ← 指向运行时常量池中该方法的引用
│ ④ 方法返回地址        │  ← 方法结束后回到哪里
└─────────────────────┘
```

---

### 三、本地方法栈（Native Method Stack）

| 属性 | 说明 |
|------|------|
| 线程属性 | 线程私有 |
| 存储内容 | Native 方法（C/C++ 实现）的调用信息 |
| 异常 | StackOverflowError / OutOfMemoryError |
| 内存来源 | JVM 内存 |

---

### 四、堆（Heap）← 内存最大的一块

| 属性 | 说明 |
|------|------|
| 线程属性 | 线程共享 |
| 存储内容 | 对象实例、数组、字符串常量池、静态变量 |
| 异常 | `java.lang.OutOfMemoryError: Java heap space` |
| 内存来源 | JVM 内存 |

#### 堆的分代结构

```
┌──────────────────────────────────────────────┐
│                    堆（Heap）                  │
├──────────────────────┬───────────────────────┤
│   新生代（Young Gen）│    老年代（Old Gen）    │
│   占堆的 1/3         │    占堆的 2/3          │
├──────────────────────┤                       │
│ Eden 区（80%）       │   长期存活的对象        │
│ Survivor 0（10%）    │   （经过多次 GC 的对象）│
│ Survivor 1（10%）    │                       │
└──────────────────────┴───────────────────────┘
```

#### 堆中还包含

```
堆（Heap）
├── 字符串常量池（String Table）   ← 全局唯一，存放所有字符串字面量对象
└── 类的静态变量（static fields）  ← 存在 Class 对象中，Class 对象也在堆中
```

#### 对象在堆中的生命周期

```
new 对象 → Eden 区
   ↓ Minor GC（存活）
Survivor 区（S0 ↔ S1 来回复制，年龄 +1）
   ↓ 年龄达到阈值（默认 15）
老年代
   ↓ Major GC / Full GC（无引用）
回收
```

---

### 五、元空间（Metaspace）← JDK 1.8 新增，替代永久代

| 属性 | 说明 |
|------|------|
| 线程属性 | 线程共享 |
| 存储内容 | 类的元信息、运行时常量池 |
| 异常 | `java.lang.OutOfMemoryError: Metaspace` |
| 内存来源 | **操作系统本地内存（Native Memory），不在 JVM 堆中** |

#### 元空间中存储的内容

```
元空间（Metaspace）
├── 类的全限定名、父类、接口信息
├── 字段（Field）描述信息
├── 方法（Method）字节码
├── JIT 编译后的本地代码
└── 运行时常量池（每个 Class 一份）
    ├── 字面量的原始数据（数值常量、字符串的 Utf8 字节内容）
    └── 符号引用（类名、方法名、字段名的字符串描述）
```

#### 运行时常量池详解

运行时常量池是 **Class 文件中常量池表的运行时表示**，类加载后复制到元空间，每个类各有一份。

**常量池中的条目类型**：

| 条目类型 | 存储内容 | 堆中有无对应对象 |
|---------|---------|---------------|
| `CONSTANT_Utf8` | 字符串的**真实字节内容** | 无（只是原始字节） |
| `CONSTANT_String` | 指向 Utf8 条目的索引 | 有，对应的 String 对象在堆中 |
| `CONSTANT_Integer/Float/Long/Double` | **真实数值** | 无（基本类型无对象） |
| `CONSTANT_Class/Fieldref/Methodref` | 名称和描述符的索引 | 有，对应的 Class/Field/Method 元数据 |

**字节码如何引用常量池**：

```
字节码指令：getfield #3
    ↓
JVM 去运行时常量池找 #3 号条目
    ↓
#3 = Fieldref → NameAndType → Utf8 "fieldName"
    ↓
去堆中 Class 对象读取对应字段的值
```

> **核心结论**：元空间存"原材料"（字节内容和索引描述），堆里存"成品对象"（真正的 Java 对象）。

## 字符串常量池（String Table）

### 存放位置

**JDK 1.8 中，字符串常量池存储在堆（Heap）中。**

### 历史演变

| JDK 版本 | 字符串常量池位置 |
|----------|-----------------|
| JDK 1.6 及之前 | 永久代（PermGen） |
| JDK 1.7 | 堆（Heap） |
| JDK 1.8 及之后 | 堆（Heap） |

### 为什么移到堆中？

1. **永久代大小固定**：启动时指定，容易 OOM，难以动态扩展
2. **GC 效率低**：永久代的 GC 回收率很低，字符串池放在里面难以回收
3. **永久代本身被废弃**：JDK 1.8 彻底删除永久代，替换为使用本地内存的元空间

### intern() 方法

`intern()` 是 String 类的本地方法，作用是将字符串对象放入字符串常量池并返回池中引用。

```java
String aa = "ab";                  // 检查池中是否有 "ab"，没有则创建并放入池中
String bb = "ab";                  // 池中已有 "ab"，直接返回池中引用
System.out.println(aa == bb);      // true，指向同一个对象

String cc = new String("ab");      // 堆上新建对象，cc 指向堆中对象
System.out.println(aa == cc);      // false

String dd = cc.intern();           // 池中已有 "ab"，返回池中引用
System.out.println(aa == dd);      // true
```

## 静态变量存在哪里？

### JDK 1.8 答案：**堆（Heap）中**

```
JDK 1.6 及之前：静态变量在永久代
JDK 1.7：        静态变量移到堆中
JDK 1.8：        静态变量仍在堆中（永久代彻底废弃）
```

### 重要区分：类的元信息 vs 静态变量

| | 类的元信息（Class Metadata） | 静态变量（static fields） |
|--|---------------------------|-------------------------|
| **内容** | 类的结构、方法字节码、常量池等 | `static` 声明的字段值 |
| **JDK 1.8 位置** | **元空间（Metaspace）** | **堆（Heap）** |
| **内存来源** | 本地内存（Native Memory） | JVM 堆内存 |

## 基本类型存在哪里？

**取决于它在哪里声明的**，基本类型的值跟着它的容器走：

| 声明位置 | 基本类型的值存在哪 |
|---------|-----------------|
| 实例变量（字段） | **堆**（在对象内部） |
| 局部变量 | **虚拟机栈**（在栈帧的局部变量表中） |
| 静态变量 | **堆**（在 Class 对象中） |

### 内存图示例

```java
public void test() {
    int count = 10;
    User user = new User();
}
```

```
虚拟机栈（栈帧）
┌──────────────────────┐
│ 局部变量表            │
│  count = 10          │  ← 10 直接存在栈里
│  user = 0x00FF       │  ← 存的是堆中对象的地址
└──────────────────────┘
         ↓ 引用
堆（Heap）
┌──────────────────────┐
│ User 对象             │
│  age = 25            │  ← 25 存在对象内部，即在堆里
│  name → "张三"       │  ← 引用，指向字符串常量池
└──────────────────────┘
```

### 基本类型与运行时常量池

只有**编译期就能确定的常量值**才会进入运行时常量池：

```java
// ✅ 进入常量池（编译期确定）
public static final int MAX = 100;       // 常量池条目 CONSTANT_Integer 100
public static final String TYPE = "hello"; // 编译期内联

// ❌ 不进常量池（运行期赋值）
int count = 100;                          // 局部变量，存在栈中
int random = new Random().nextInt();      // 运行期才知道值
static final Person p = new Person();     // 运行期 new，对象在堆中
```

## 完整对照表

| 区域 | 线程属性 | 存储内容 | 异常 | 内存来源 |
|------|---------|---------|------|---------|
| 程序计数器 | 私有 | 当前执行的字节码行号 | 无 | JVM 内存 |
| 虚拟机栈 | 私有 | 栈帧（局部变量、操作数栈等） | StackOverflowError / OOM | JVM 内存 |
| 本地方法栈 | 私有 | Native 方法的调用信息 | StackOverflowError / OOM | JVM 内存 |
| **堆** | **共享** | **对象、数组、字符串常量池、静态变量** | **OOM: Java heap space** | **JVM 内存** |
| **元空间** | **共享** | **类元信息、运行时常量池** | **OOM: Metaspace** | **本地内存** |

## 一个对象创建时的完整内存分布

```java
public class User {
    public static String TYPE = "ADMIN";   // 静态变量
    private String name;                   // 实例变量

    public User(String name) {
        this.name = name;
    }
}

User u = new User("张三");
```

```
程序计数器：指向当前执行行

虚拟机栈（栈帧）：
  局部变量表：u（引用）→ 指向堆中 User 对象

堆（Heap）：
  字符串常量池：
    "ADMIN" 对象
    "张三" 对象

  User 对象实例：
    name 字段 → 指向 "张三"

  User.class 对象（Class 元数据实例）：
    TYPE 字段 → 指向 "ADMIN"

元空间（Metaspace）：
  User 类元信息：类名、字段描述、方法字节码
  User 的运行时常量池：描述 "ADMIN"、"张三" 等字面量的索引条目（Utf8 字节）
```

## 常见疑问解答

### 疑问：字符串常量池和运行时常量池都存了字符串，有什么区别？

**运行时常量池**存的是字符串的**原始字节内容（Utf8 数据）**，在元空间中；
**字符串常量池**存的是真正的 **`java.lang.String` 对象**，在堆中。

两者关系：运行时常量池中的 `CONSTANT_String` 条目指向 Utf8 字节，JVM 执行 `ldc` 指令时，根据这个字节去堆的字符串常量池中查找或创建对应的 String 对象。

> 类比：运行时常量池是"快递单"（记录地址），字符串常量池是"仓库"（存放真实包裹）。

---

### 疑问：运行时常量池"不存真实对象，只存描述信息和索引关系"，对吗？

**大体正确，但需要补充**：运行时常量池里确实存了一些真实数据：

- `CONSTANT_Utf8` 条目存的是**真实的字节内容**（"ADMIN" 的 5 个字节）
- `CONSTANT_Integer/Float` 存的是**真实的数值**（100、3.14）

但这些**不是 Java 对象**，只是原始数据。真正的 `java.lang.String` 对象在堆中。

> 更准确的说法：元空间存"原材料"（字节和数值），堆里存"成品对象"（Java 对象）。

---

### 疑问：`static final String TYPE = "ADMIN"` 和 `static String NAME = "ADMIN"` 有冲突吗？

不冲突，区别在 `final` 关键字：

| | `static final`（常量） | `static`（变量） |
|--|----------------------|----------------|
| **能否修改** | 不能，编译期就确定值 | 能，运行期可以改变 |
| **编译器优化** | ✅ **直接内联替换** | ❌ 不内联 |
| **实际存储** | 编译器把所有使用处替换为字面量，字面量在堆的字符串常量池 | 变量存在堆中 Class 对象里 |

字节码验证：

```
// static final String TYPE = "ADMIN"
// 使用 TYPE 的地方：
ldc  #4    // String "ADMIN"  ← 内联为字面量，直接加载

// static String NAME = "ADMIN"
// 使用 NAME 的地方：
getstatic  Demo.NAME         ← 必须从字段读取，不能内联
```

---

### 疑问：`static final Person person = new Person()` 存在哪？

**堆中**（不进常量池）。

虽然加了 `static final`，但 `new Person()` 是运行期才能执行的操作，编译器无法在编译时知道这个对象的内容，因此：

- `person` 字段 → 存在**堆中的 Class 对象**里
- `Person` 对象 → 存在**堆**中
- 常量池中**只有字段的描述信息**（字段名、类型），没有对象数据

> 只有**基本类型/String + 编译期可确定的值**才是编译期常量，才能进入常量池。

---

### 疑问：JDK 1.8 中字符串常量池为什么放在堆中？

永久代存在三个严重问题：大小固定（容易 OOM）、GC 回收率低、永久代本身被废弃。

JDK 1.7 把字符串池从永久代搬到堆中，JDK 1.8 彻底删除永久代替换为元空间。元空间使用本地内存，只存类元信息，字符串池自然留在堆中，由成熟的分代 GC 统一管理。

---

### 疑问：JVM 内存结构中，HotSpot 是什么？

**HotSpot 是 Oracle（原 Sun）官方提供的 Java 虚拟机实现**，是目前使用最广泛的 JVM，我们日常说的"JVM"默认指的就是 HotSpot。

HotSpot 的名字来源于它的核心能力：**找出代码中频繁执行的"热点"（Hot Spot），对这些热点代码进行 JIT 编译优化**，将字节码编译成本地机器码，执行速度提升 10~100 倍。

---

## 一句话总结

> JDK 1.8 的 JVM 内存分为**线程私有**（程序计数器、虚拟机栈、本地方法栈）和**线程共享**（堆、元空间）两大类；**堆**存放对象、数组、字符串常量池和静态变量；**元空间**（本地内存）存放类元信息和运行时常量池；字符串对象始终在堆中，元空间中只存其字节描述。
