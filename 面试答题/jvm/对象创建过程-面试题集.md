## 第 1 题：对象创建流程

### 题目

**请描述 HotSpot 1.8 中，执行 `new User("张三")` 时，JVM 底层经历了哪些步骤，从字节码被解释执行开始，到对象最终可用为止？**

---

### 我的回答

1. 类加载检查，如果类未加载，就走类加载步骤加载到元空间，已加载就跳过
2. 分配内存，根据基本类型和对象引用分配对应的内存
3. 内存空间初始化，对基本类型进行初始化
4. 对象头创建，比较重要的有 hashCode、对象的年龄、类型指针、偏向锁 ID、锁类型（偏向/轻量/重量）
5. 执行 init，也就是构造方法
6. 返回引用

---

### 评分：6 / 10 分

**答对的部分：**
- ✅ 6 个步骤的框架完整
- ✅ 类加载检查描述准确
- ✅ 对象头内容列举得很全（hashCode、分代年龄、类型指针、偏向锁 ID、锁类型）
- ✅ 返回引用提到了

**需要补充的部分：**

步骤 ② 分配内存（描述较笼统）：
- 内存分配在**堆的 Eden 区**，不是"根据类型分配"
- 两种分配方式：**指针碰撞**（内存规整时）vs **空闲列表**（内存不规整时，如 CMS）
- 并发安全方案：**TLAB 优先**（每个线程私有缓冲区，无锁），TLAB 用完或大对象才走 **CAS**

步骤 ③ 零值初始化（漏了引用类型）：
- 不只是基本类型，**引用类型也初始化为 `null`**
- 嵌套对象（如 `new Address()`）此时**未创建**，只有 null 引用

步骤 ⑤ 执行 `<init>`（顺序不完整）：
- 完整执行顺序：**父类构造方法 → 字段声明赋值 → 实例代码块 → 构造方法体**

---

### 参考答案

> ① **类加载检查**：检查 User 是否已加载到元空间，未加载则触发类加载流程（加载 → 验证 → 准备 → 解析 → 初始化），已加载则直接跳过。
>
> ② **分配内存**：在堆的 Eden 区分配，内存规整时用指针碰撞（移动指针），不规整时用空闲列表（查找空闲块）；多线程下 TLAB 优先（每个线程有私有缓冲区，无锁分配），TLAB 用完或大对象走 CAS + 失败重试。
>
> ③ **零值初始化**：将对象内存（不含对象头）全部置为零值，基本类型为 0/false，**引用类型为 null**，嵌套对象此时未创建，只有 null 引用，在构造方法阶段才会创建。
>
> ④ **设置对象头**：写入 Mark Word（hashCode、分代年龄、锁状态标志、偏向线程 ID）和 Klass Pointer（指向元空间中该类的元信息）。数组对象还额外写入数组长度。
>
> ⑤ **执行 `<init>`**：按顺序执行父类构造方法 → 字段声明赋值 → 实例代码块 → 构造方法体。此阶段覆盖零值，赋真实初始值，嵌套对象在此阶段通过 new 创建。
>
> ⑥ **返回引用**：将新对象的内存地址赋给栈中的局部变量，对象创建完成。

---

### `<init>` 执行顺序案例

```java
class Parent {
    public Parent() {
        System.out.println("① 父类构造方法");
    }
}

class Child extends Parent {
    private String name = initName();       // 字段声明赋值

    {
        System.out.println("③ 实例代码块 A");
    }

    private Address address = new Address(); // 字段声明赋值（创建嵌套对象）

    {
        System.out.println("④ 实例代码块 B");
    }

    public Child() {
        super();  // 隐式调用，触发父类构造
        System.out.println("⑤ 子类构造方法体");
    }

    private String initName() {
        System.out.println("② 字段声明赋值：name");
        return "张三";
    }
}

// 执行
new Child();
```

**输出结果**：

```
① 父类构造方法
② 字段声明赋值：name
③ 实例代码块 A
④ 实例代码块 B
⑤ 子类构造方法体
```

> **规则**：字段赋值和实例代码块按**源码书写顺序交叉执行**，不是先执行所有字段再执行代码块。

## 第 2 题：TLAB 与 CAS 的协作机制

### 题目

**多线程环境下，HotSpot 如何保证对象内存分配的线程安全？请详细描述 TLAB 的工作机制，以及大对象（如 `new byte[1024*1024]`）是如何处理的？**

---

### 我的回答

使用 TLAB，每个线程有一个私有的内存，如果这个内存空间够，就直接使用，如果不够，就走 CAS 和其他对象竞争。

---

### 评分：6 / 10 分

**答对的部分：**
- ✅ TLAB 每个线程有私有缓冲区，空间够直接分配（无锁）
- ✅ TLAB 不够时走 CAS 竞争

**需要补充的部分：**

TLAB 不够时走 CAS，具体是申请"新的 TLAB"，不是直接分配对象：
- TLAB 满了 → CAS 向 Eden 区申请一块**新的 TLAB** → 成功后在新 TLAB 里分配对象

大对象完全跳过 TLAB：
- 对象大小超过 TLAB 容量（默认约 Eden 的 1%，几十 KB）
- 直接走 CAS 在 Eden 区分配，**不经过 TLAB**

CAS 失败后的处理：
- CAS 失败 → **重试**，直到成功（乐观锁思想）

---

### 参考答案

> **TLAB（Thread Local Allocation Buffer）**：每个线程在 Eden 区预分配一块私有缓冲区（默认约 Eden 的 1%），线程在自己 TLAB 中分配内存**无需加锁**，极快。
>
> **完整分配优先级**：
> ```
> TLAB 中分配（首选，无锁）
>     ↓ TLAB 空间不足
> CAS 向 Eden 申请新 TLAB（失败则重试）
>     ↓ 对象大小超过 TLAB 容量（大对象）
> 直接 CAS 在 Eden 区分配（跳过 TLAB）
> ```
>
> 以 `new byte[1024*1024]`（1MB）为例：默认 TLAB 只有几十 KB，装不下，**直接走 CAS 在 Eden 分配**，不经过 TLAB。
>
> TLAB 默认开启，参数：`-XX:+UseTLAB`（开启）、`-XX:TLABSize=N`（调整大小）。

---

### 疑问：TLAB 可以一直申请吗？什么时候释放？

**TLAB 是 Eden 区的一部分，跟着 Eden 一起被 GC 回收，不需要单独释放。**

```
完整生命周期：

应用启动 → 各线程分配初始 TLAB
    ↓
线程在 TLAB 中无锁分配对象
    ↓ TLAB 用完
CAS 申请新 TLAB（从 Eden 剩余空间划一块）
    ↓ 不断重复...
Eden 区整体快满了
    ↓
触发 Minor GC → Eden 清空（所有旧 TLAB 一并消失）
    ↓
存活对象移到 Survivor 区，Eden 重新为空
    ↓
各线程重新分配新 TLAB，继续循环
```

不会无限申请的两道保护：
1. **Eden 空间有限**：Eden 满了就触发 GC，GC 后重新分配
2. **GC 回收无用对象**：如果 GC 后仍放不下 → 才报 `OutOfMemoryError`

class BaseOrder {

public class Order extends BaseOrder {

### 我的回答

执行顺序：baseId = "BASE001" → quantity = 10 → name = "默认订单" → address = new Address("上海") → this.name = "正式订单"

**答对的部分：**
- ✅ `<init>` 阶段的执行顺序完全正确
- ✅ 知道父类字段先执行

**需要补充的部分：**

漏掉了**零值初始化阶段**，这是题目的核心考点之一。

---

### 参考答案

**各字段值变化全过程：**

## 第 4 题：对象头结构详解

### 题目

**请描述 HotSpot 1.8 中对象头（Object Header）的结构，Mark Word 中包含哪些信息？Klass Pointer 指向哪里？数组对象和普通对象的对象头有什么区别？**

---

### 我的回答

Mark Word 包含 hashCode，用途判断对象是否相等，先判断 hashCode 再判断内容，比如 HashSet，hashCode 相等在同一个桶中，后面再根据对象是否相等存链表或者红黑树。对象年龄，垃圾回收使用，对象年龄大于 N 就放到老年代中。偏向锁 ID，并发时会用，当一个线程无并发就直接进入。锁类型 偏向/轻量/重量。数组对象有数组长度。

---

### 评分：6 / 10 分

**答对的部分：**
- ✅ hashCode，并解释了 HashSet 的实际应用场景
- ✅ 对象年龄，正确描述了超过阈值进入老年代
- ✅ 偏向锁 ID，解释了无竞争直接进入
- ✅ 锁类型：偏向/轻量/重量
- ✅ 数组对象额外有数组长度

**需要补充的部分：**

Klass Pointer 完全没有提到：
- 对象头除了 Mark Word，还有 **Klass Pointer（类型指针）**
- 开启指针压缩为 **4 字节**，关闭为 **8 字节**
- 指向**元空间中该类的元信息**，JVM 通过它判断对象是哪个类的实例

对象头的完整大小：
- 开启指针压缩：Mark Word 8 + Klass Pointer 4 = **12 字节**
- 关闭指针压缩：Mark Word 8 + Klass Pointer 8 = **16 字节**

---

### 参考答案

**HotSpot 1.8 对象头结构（64 位 JVM，开启指针压缩）**：

```
对象头（普通对象共 12 字节）
┌──────────────────────────────────────────────┐
│ Mark Word（8 字节）                           │
│  - hashCode：对象哈希码，用于哈希表快速定位     │
│  - GC 分代年龄（4 bit，0~15）：超过阈值进入老年代│
│  - 锁状态标志（2 bit）：无锁/偏向/轻量/重量    │
│  - 偏向线程 ID：偏向锁状态下记录独占线程        │
├──────────────────────────────────────────────┤
│ Klass Pointer（4 字节，开启压缩）              │
│  → 指向元空间中该类的元信息（类名、方法、字段等）│
└──────────────────────────────────────────────┘

数组对象额外多出 4 字节：
┌──────────────────────────────────────────────┐
│ 数组长度（4 字节）                             │
└──────────────────────────────────────────────┘
数组对象对象头 = 12 + 4 = 16 字节
```

**Klass Pointer 的作用**：
- JVM 通过它找到类的元信息，判断对象是哪个类的实例
- `instanceof` 判断、虚方法调用都依赖它

## 第 5 题：对象内存大小计算

### 题目

**以下代码创建的 `Student` 对象，其内存大小是多少字节？请写出计算过程。（64 位 JVM，开启指针压缩）**

```java
public class Student {
    private int age;           // 4 字节
    private boolean active;    // 1 字节
    private String name;       // 引用
    private int[] scores;      // 引用
}
```

---

### 我的回答

- int age = 4 字节
- boolean active = 1 字节
- String name = 4 字节（引用）
- int[] scores = 4 字节（引用）
- 对象头 16 字节，还有对齐

---

### 评分：7 / 10 分

**答对的部分：**
- ✅ 各字段大小计算正确
- ✅ 知道需要对齐填充

**需要纠正的部分：**

对象头你算成了 16 字节，实际是 12 字节（开启指针压缩）：
- Mark Word = 8 字节
- Klass Pointer = 4 字节（开启压缩）
- **对象头合计 = 12 字节**（不是 16）

> 16 字节是**数组对象**的对象头（12 + 4 字节数组长度），普通对象只有 12 字节。

---

### 参考答案

```
对象头          = 12 字节（Mark Word 8 + Klass Pointer 4）
int age         =  4 字节
boolean active  =  1 字节
String name     =  4 字节（引用，开启压缩）
int[] scores    =  4 字节（引用，开启压缩）
─────────────────────────
字段合计         = 13 字节
原始总计         = 12 + 13 = 25 字节
对齐到 8 的倍数  → 32 字节（填充 7 字节）

最终大小：32 字节
```

> 注意：HotSpot 实际上会对字段**重排序**优化（把 4 字节字段排在一起，1 字节字段放最后），可以减少填充浪费，但考试题按顺序算即可。

## 第 6 题：字符串常量池与 == 比较

### 题目

**请解释以下代码的输出结果，并说明原因：**

```java
String a = "hello";
String b = "hello";
String c = new String("hello");
String d = new String("hello");

System.out.println(a == b);        // ?
System.out.println(a == c);        // ?
System.out.println(c == d);        // ?
System.out.println(c.intern() == a); // ?
```

---

### 我的回答

- `a == b` → true，字符串常量池
- `a == c` → false，不同的对象
- `c == d` → false，不同的对象
- `c.intern() == a` → true，intern 把 c 的放到常量池，并且返回

---

### 评分：9 / 10 分

**答对的部分：**
- ✅ 四个结果全部正确
- ✅ a == b 解释了常量池
- ✅ a == c、c == d 解释了不同对象

**小扣分点（#4 的解释不够精确）：**

你说“intern 把 c 放到常量池”，更准确的说法：
> `"hello"` 已经存在于常量池中（由 `a = "hello"` 放入），`c.intern()` 发现池中已有相同字符串，**直接返回池中已有的引用（就是 a）**，并没有把 c 放进去。
>
> 只有池中**没有**时，才会把 c 的引用存入池中并返回（JDK 1.7+ 行为）。

---

### 参考答案

```java
String a = "hello";              // 检查常量池，无 → 创建 "hello" 放入池，a 指向池中对象
String b = "hello";              // 检查常量池，有 → 直接返回池中引用，b == a
String c = new String("hello");  // new 在堆上新建对象，c 指向新对象（与池中无关）
String d = new String("hello");  // 同上，d 指向另一个新对象

a == b          // true  → 都指向常量池中同一个 "hello"
a == c          // false → a 指向池中对象，c 指向堆上新对象，地址不同
c == d          // false → 两次 new，两个不同的堆对象
c.intern() == a // true  → 池中已有 "hello"（就是 a），intern 返回池中引用，等于 a
```

## 第 7 题：字符串常量池与运行时常量池

### 题目

**请解释 JDK 1.8 中字符串常量池为什么从永久代移到了堆中？运行时常量池和字符串常量池有什么区别？它们分别存在哪里？**

---

### 我的回答

字符串常量池，永久代移 FULL GC 才释放，到堆可以更快释放，还有大小堆是弹性的。运行时常量池是在元数据中，里面存储的字面量、符号引用等。字符串常量池是在堆中，存的是字符串的常量。

---

### 评分：8 / 10 分

**答对的部分：**
- ✅ 永久代需要 Full GC 才能释放，移到堆后可以更快被 Minor GC 回收
- ✅ 堆大小是弹性的，永久代大小固定
- ✅ 运行时常量池在元空间中，存字面量、符号引用
- ✅ 字符串常量池在堆中，存字符串常量

**需要补充的部分：**

两个池的本质区别没有点透：

| | 运行时常量池 | 字符串常量池 |
|--|-------------|-------------|
| **位置** | 元空间（本地内存） | 堆（JVM 内存） |
| **存的内容** | Utf8 **原始字节** + 符号引用索引 | 真正的 `java.lang.String` **对象** |
| **数量** | 每个类一份 | 全局唯一 |

> 运行时常量池是“快递单”（描述信息），字符串常量池是“仓库”（真实对象）。

永久代还有一个重要问题：
- 永久代**大小固定**（-XX:MaxPermSize 设定），设小了容易 `OOM: PermGen space`，设大了浪费内存

---

### 参考答案

**为什么移到堆中：**
1. 永久代大小固定，启动后不能变，容易 OOM
2. 永久代 GC 回收率极低，字符串池中的对象难以被回收
3. 堆可以动态扩展，GC 算法成熟（分代收集），移到堆后内存管理更高效
4. 永久代本身被废弃，JDK 1.8 整体替换为元空间

**两个池的区别：**

| | 运行时常量池 | 字符串常量池 |
|--|-------------|-------------|
| **位置** | 元空间（本地内存） | 堆（JVM 内存） |
| **存的内容** | Utf8 原始字节 + 符号引用索引 | 真正的 `java.lang.String` 对象 |
| **数量** | 每个类一份 | 全局唯一 |
| **生命周期** | 随类的卸载而回收 | 随 GC 回收 |

> 元空间存“原材料”（字节内容），堆里存“成品对象”（String 对象）。

## 第 8 题：static final 与 static 的 JVM 处理方式

### 题目

**以下代码，`static final` 和 `static` 声明的字符串，在 JVM 中的处理方式有何不同？请从字节码和内存两个角度解释。**

```java
public class Demo {
    public static final String TYPE = "ADMIN";   // ①
    public static String NAME = "ADMIN";         // ②

    public void test() {
        System.out.println(TYPE);
        System.out.println(NAME);
    }
}
```

---

### 我的回答

- `static final String TYPE = "ADMIN"`：编译确定了，在元空间，运行时常量
- `static String NAME = "ADMIN"`：堆中，可以改变，字符串常量

---

### 评分：6 / 10 分

**答对的部分：**
- ✅ `static final` 是编译期确定的
- ✅ `static String NAME` 在堆中，可以修改

**需要纠正的部分：**

`static final String TYPE = "ADMIN"` 并不是存在元空间：
- `"ADMIN"` 这个 String 对象**始终在堆的字符串常量池中**，不管是 `final` 还是非 `final`
- 元空间里只存了 Utf8 字节描述，不存 String 对象

漏掉了核心考点：**编译期内联**：
- `static final`：编译器把所有使用 TYPE 的地方**直接替换为字面量**，字节码用 `ldc` 加载
- `static`：编译器不能内联，必须从字段读取，字节码用 `getstatic`

---

### 参考答案

**字节码角度：**

```java
// 使用 TYPE 的地方（编译期内联）：
ldc  #4    // String "ADMIN"  ← 直接加载字面量，不访问 TYPE 字段

// 使用 NAME 的地方（必须从字段读取）：
getstatic  Demo.NAME          ← 去堆中 Class 对象里读 NAME 字段
```

**内存角度：**
- `"ADMIN"` String 对象 → 始终在堆的字符串常量池中（两者都一样）
- TYPE 字段（堆中 Class 对象）→ 存在，但运行时基本不被访问（已被内联）
- NAME 字段（堆中 Class 对象）→ 每次使用都要读取

**成为编译期常量的三个条件：**
1. `final` 修饰
2. 基本类型或 String
3. 用**编译期可确定的常量表达式**初始化

> `static final Person p = new Person()` 不是编译期常量（`new` 是运行期操作），不能内联。

## 第 9 题：intern() 在 JDK 1.7+ 的行为

### 题目

**以下代码，`s1 == s2`、`s1 == s3`、`s2 == s3` 的结果分别是什么？请解释 JDK 1.7+ 下 `intern()` 的行为。**

```java
String s1 = new String("a") + new String("b");
String s2 = s1.intern();
String s3 = "ab";
```

---

### 我的回答

- `s1 == s2` → true
- `s1 == s3` → true
- `s2 == s3` → true

---

### 评分：10 / 10 分

三个结果全部正确！

---

### 参考答案

**执行过程：**

```java
String s1 = new String("a") + new String("b");
// s1 = "ab"，在堆上新建的对象
// 注意："ab" 此时并不在字符串常量池中（运行期拼接，不是字面量）

String s2 = s1.intern();
// 检查常量池：没有 "ab"
// JDK 1.7+：把 s1 指向的对象的引用直接存入常量池（不复制对象）
// s2 = s1（同一个引用）→ s1 == s2 = true

String s3 = "ab";
// 检查常量池：已有 "ab"（就是 s1 的引用）
// s3 = s1（同一个引用）→ s1 == s3 = true，s2 == s3 = true
```

**JDK 1.7+ 的 `intern()` 行为变化：**

| JDK 版本 | 池中不存在时的行为 |
|---------|------------------|
| JDK 1.6 | 把对象**复制一份**放入永久代的字符串池 |
| **JDK 1.7+** | **直接存储堆中对象的引用**（不复制），所以 `s1 == s2` |
